EnzymeImplicitAD — Module

EnzymeImplicitAD.jl

The purpose of this Julia package is to organize solution and automatic differentiation of implicit problems, described mathematically as

\[F(x, y(x)) = 0\]

which define $y$ as an implicit function of $x$.

We use the term “implicit problem” for an implicit function associated with metadata, such as problem dimensions, solution statistics.

The API of this package

  1. helps define problems of this kind with a simple interface, implemented by the user,

  2. implements functions for checking and benchmarking user implementations,

  3. provides various wrappers that handle caching of values, recording or failed solutions, preallocation of buffers.

The package does not export any symbols, merely makes them public. It is recommended that the user imports the package with a short alias, such as in

import EnzymeImplicitAD as EI

Motivation

I wrote this package because:

  1. I want to understand automatic differentiation better.
  2. I want to understand how Enzyme works.
  3. Serve as an MWE for asking questions.
  4. Eventually, potentially contribute to ImplicitDifferentiation.jl, once I figure out how the details work.

Q & A

Are you following SemVer?

Technically yes, since the package will be kept at v0.x, so everything is assumed to be breaking 😉

Can I use this in production code?

The code is intended to be usable, with unit tests, and if you commit the manifest it will be reproducible. Note that this is still work in progress though, and be ready for breaking changes.

Will this package be registered/released eventually?

Yes. If I finish experimentation and arrive at a stable API, it will either be contributed into an existing package, or cleaned up significantly and then released under a different name.

Example

An example implementation of a univariate cube root (which, of course, Julia already knows how to do with cbrt, this is just an example):

import EnzymeImplicitAD as EI

"Solving ``x - y^3 = 0`` for single-element vectors."
struct UniCubeRoot end

EI.get_dimensions(::UniCubeRoot) = (; n_x = 1, n_y = 1, n_r = 1)
EI.implicit_residuals!(r, ::UniCubeRoot, x, y) = (r[1] = only(x) - only(y)^3; nothing)
EI.get_initial_guesses(P::UniCubeRoot, x) = [x]
function EI.implicit_solve_with_initial_guesses!(y, P::UniCubeRoot, x; initial_guesses)
    _x = only(x)
    _y = first(initial_guesses)[1]
    ϵ = √max(eps(_x), eps(typeof(_x))) # tolerance, up to the solution method
    for _ in 1:precision(_x)
        if abs(_x - _y^3) ≤ ϵ
            y[1] = _y
            return true
        end
        _y = (2*_y + _x / _y^2) / 3
    end
    false # failed to find root within given number of steps, will not happen here
end

EI.sanity_checks(UniCubeRoot())
✔ all checks passed

Note how we implement the method which uses initial guesses, which makes wrappers easy to use. However, someone using this implementation would use

P = UniCubeRoot()
(; n_y) = EI.get_dimensions(P)
y = zeros(n_y)
EI.implicit_solve!(y, P, [8.0])
y
1-element Vector{Float64}:
 2.000000001071189

which calculates the initial guesses (where applicable), and passes them on to the implementation above. This is the method through which AD operates.

Where to go from here

Refer to the documentation of the implicit problem api for defining problems. Note, however, that in most case only a few key methods are needed for defining a problem.

Benchmarking and sanity checks help the user debug and optimize problem implementations.

Wrappers add useful functionality to a user-defined problem, including caching solutions and residuals, collecting statistics, preallocating buffers.

In most cases, the user should not have to deal with the nuts and bolts of automatic differentiation, but they can be customized.
