The implicit problem API

The purpose of this package is to isolate an implicit problem in part of the code, and make it differentiable. The table below summarizes the whole API that each problem must support. A convenient way to confirm this is with sanity_checks.

The key entry point is

EnzymeImplicitAD.implicit_solve! — Function
implicit_solve!(y, implicit_problem, x) -> success::Bool

Solve the implicit problem $F(x, y(x)) = 0$ at x, overwriting y with $y(x)$ result.

When success, the result is put in y. When !success, the contents of y (and, consequently, the pullback/pushforward in AD) are undefined. Implementations are encouraged, but not required, to fill the latter with NaNs.

See implicit_residuals!, which implements $g$ above.

Note

Don't specialize this method, rather get_initial_guesses, implicit_solve_with_initial_guesses!.

Minimal conforming implementation

A problem has to implement at least the following methods:

  1. EnzymeImplicitAD.get_dimensions,
  2. EnzymeImplicitAD.implicit_residuals!,
  3. EnzymeImplicitAD.implicit_solve_with_initial_guesses!

Importantly, this package is agnostic about the solver; you can use whichever method you want.

Residuals and solvers

These describe the function $F(x, y)=0$ and the solution method for y. Importantly, solutions can fail.

EnzymeImplicitAD.implicit_residuals! — Function
implicit_residuals!(r, implicit_problem, x, y) -> nothing

Calculate the implicit residuals $r = F(x, y)$, overwriting r.

It is assumed that after

implicit_solve!(y, implicit_problem, x)
implicit_residuals!(r, implicit_problem, x, y)

the residuals r are “approximately” zero, but this is not checked.

source
EnzymeImplicitAD.implicit_solve_with_initial_guesses! — Function

Solve for y with implicit_problem at x. initial_guesses is a vector of initial guesses for y (may be empty).

When success, the result is put in y. When !success, the contents of y are undefined.

Methods are implemented outside this package.

Initial guesses

A good initial guess is very useful when solving an implicit problem numerically. Implementing the method below allows solvers to use these guesses in a convenient manner also via wrappers.

EnzymeImplicitAD.get_initial_guesses — Function
get_initial_guesses(
    problem,
    x
) -> AbstractVector{<:AbstractVector{eltype(x)}}

Provide initial guess(es) for the problem given x, as a vector of vectors. May be empty. The most useful initial guesses should come first.

Caller can assume that the dimensions are correct.

Threads

Implementations are not required to be thread-safe. Rather, the caller should be able to create a thread-local copy.

EnzymeImplicitAD.independent_copy — Function
independent_copy(x)

Make a copy of problem that functionally equivalent but independent, ie safe for using in another thread. Specifically, this should ensure that all the functions in the API of this package are safe to use concurrently on independent copies.

The generic method makes an effort to just return recursively immutable values as is, but it may just be too narrow. If it fails, define a method for the type.

Statistics

While problems are being solved, they may collect statistics about their solution. The user can query these with

EnzymeImplicitAD.get_statistics — Function
get_statistics(implicit_problem) -> statistics::NamedTuple

Return various statistics that are accumulated during calls, that may help the user evaluate and tune algorithms.

source

Solution concepts (ignore for now)

Currently, the interface supports only the implicit function formulation. The following API is for future extensions, allowing least squares or fixed point formulations.

EnzymeImplicitAD.get_solution_concept — Function
get_solution_concept(implicit_problem) -> solution_concept

Return the solution concept. The default is ZeroResiduals, which is currently the only supported solution concept.

source
EnzymeImplicitAD.ZeroResiduals — Type

Solution concept: for a given x, y is the solution which makes residuals r zero in implicit_residuals!(r, problem, x, y).
